# ChitChat v3.9.0

`v3.9.0` closes a privacy gap in the event stream, lets administrators and room owners hand a room to a new owner, and continues the Lantern redesign with the Rooms, Direct, Activity and search lists. It also fixes unread counts for members who never opened a room, and stops the event stream rescanning old events. API v1 changes are additive. It adds three forward-only database migrations (`0056` to `0058`) and needs no configuration changes, so back up before upgrading. Nobody is signed out.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It continues the maintainer-approved presentation overhaul and adds maintainer-approved room administration, all tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Security and privacy

- **Removed or edited message text is no longer replayed.** ([#276](https://github.com/Thiesi/ChitChat/issues/276), [#280](https://github.com/Thiesi/ChitChat/pull/280)) Before, a member who joined a room later, or reconnected after being offline, could receive a message's text as it was first sent, even after it had been deleted (including by a moderator) or edited. This also applied inside a reply's quote and in direct messages. Room events now start at the account's current membership, and replayed messages show their current state. **Upgrade soon.**

## Added

- **Transfer room ownership.** ([#273](https://github.com/Thiesi/ChitChat/issues/273), [#277](https://github.com/Thiesi/ChitChat/pull/277))
  - The current owner, or a Super-Administrator, Administrator or Chat Admin, can hand a room to another registered member who isn't banned from it. This requires a fresh privileged confirmation.
  - An administrator can also take over a room they aren't in, for example one whose owner has closed their account. The room's minimum age still applies.
  - The previous owner stays in the room as a moderator, or as a member if their account is closed or closing. Both are told in Activity, without a phone alert. The transfer is recorded in the audit log.
  - A room now always has exactly one owner. The database enforces it, and leaving, role changes and removals can no longer race a transfer into a room without an owner.
  - For app developers: `POST /api/v1/rooms/transfer-ownership.php`, and notifications `room_ownership_received` and `room_ownership_removed`. See [`docs/api/rooms.md`](../api/rooms.md).
- **"@" on the Rooms list counts every unread mention.** ([#266](https://github.com/Thiesi/ChitChat/issues/266), [#267](https://github.com/Thiesi/ChitChat/pull/267)) Before, it was derived from the newest notifications only, and missed older ones.
- **For app developers, also additive:**
  - `rooms/list.php` gains `unread_mention_count` (capped at 100) and `unread_through_message_id`, and the join response gains the read fields ([#267](https://github.com/Thiesi/ChitChat/pull/267), [#269](https://github.com/Thiesi/ChitChat/pull/269));
  - each row of `direct-messages/conversations.php` gains `user.available` and `relationship` (`blocked_by_me`, `messaging_available`), with the same meaning and privacy as `block-status.php` ([#274](https://github.com/Thiesi/ChitChat/issues/274), [#275](https://github.com/Thiesi/ChitChat/pull/275)).

## Changed

- **Rooms, Direct, Activity and search lists (Lantern redesign S4).** ([#170](https://github.com/Thiesi/ChitChat/issues/170); [#265](https://github.com/Thiesi/ChitChat/pull/265), [#278](https://github.com/Thiesi/ChitChat/pull/278), [#282](https://github.com/Thiesi/ChitChat/pull/282), [#284](https://github.com/Thiesi/ChitChat/pull/284))
  - **Rooms:** grouped, with presence, the time of the latest message, an "@" for unread mentions and a card listing them.
  - **Direct:** each conversation shows its time and whether the other person is blocked or unavailable, or the conversation is closed. The list refreshes only when something changed.
  - **Activity:** grouped under day headings, with a mark for each kind of notice and the server's own wording first.
  - **Search:** results are rows with the matched words highlighted, plus chips to narrow the scope.
  - Every list is a real list of links, so screen readers and keyboards move through it as one.
- **You is split into sections (Lantern redesign S5, first part).** ([#171](https://github.com/Thiesi/ChitChat/issues/171), [#287](https://github.com/Thiesi/ChitChat/pull/287))
  - Profile, Alerts, Appearance, Sign-in and security, Privacy and Account each have their own page and address (for example `/account.php#security`), listed under your picture and name. Sign out (Leave for guests) is the last row, and for staff, Stewarding is the first.
  - On phones You opens on the list, and a section opens full screen; Back returns to the list.
  - Profile shows your username and "Member since", and a link to choose a new username if a moderator asked for one.
  - Old links and bookmarks still open the right section, and returning from Google or Twitch sign-in lands in Sign-in and security.
  - The typing indicator setting is now a switch. Choosing a section moves focus to its title.
  - What each setting does is unchanged, including every confirmation step.

## Fixed

- **Unread counts for members who never opened a room.** ([#268](https://github.com/Thiesi/ChitChat/issues/268), [#269](https://github.com/Thiesi/ChitChat/pull/269)) Their count stayed at zero forever, and rejoining a room counted the whole absence as unread. The read position now starts when you join or create a room.
- **Reconnecting after a long time is fast again.** ([#281](https://github.com/Thiesi/ChitChat/issues/281), [#285](https://github.com/Thiesi/ChitChat/pull/285)) The event stream no longer rescans old events it can't deliver to you on every check. On a busy installation, each check drops from most of a second to a few milliseconds. Replayed messages also show the sender's current name.
- **A moderator removing a profile picture** while requiring a new username for the same person no longer risks a failed request. ([#262](https://github.com/Thiesi/ChitChat/issues/262), [#264](https://github.com/Thiesi/ChitChat/pull/264))

## What to evaluate

Operators staging this release should check that:
- the Rooms, Direct, Activity and search lists look and work right on a desktop, a tablet-sized window and a phone;
- a room owner can transfer ownership to a member after the privileged confirmation (password, passkey or authenticator code), and both people see the notice in Activity;
- a member who joins a room and receives messages sees an unread count;
- a deleted message does not reappear after another device reconnects.

## Database changes

All three migrations are forward-only:
- `0056_room_unread_mentions.sql`: a partial index on unread room-mention notifications.
- `0057_room_read_start.sql`: gives existing members who have no read position one at the room's newest message, so nothing old suddenly counts as unread.
- `0058_room_ownership.sql`: a unique index allowing one owner per room. **It stops, naming each affected room, if a room already has more than one owner, and changes nothing.** Check first with this read-only query, which must return no rows:
  ```sql
  SELECT room_id, COUNT(*) AS owners FROM room_members WHERE role = 'owner' GROUP BY room_id HAVING COUNT(*) > 1;
  ```

`0056` and `0058` build their indexes without `CONCURRENTLY`, so writes to `account_notifications` and `room_members` wait while each is built. Run the upgrade with writes drained, as in the steps below.

## Upgrade from v3.8.0

1. Run the read-only owner check above. If it returns rows, resolve them before upgrading.
2. Stop or drain application writes (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
3. Deploy `v3.9.0` source.
4. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` applies `0056`, `0057` and `0058`.
5. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
6. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.9.0`.

Upgrading from before `v3.8.0` also applies that release's migrations (`0053` to `0055`); read its release notes first.
