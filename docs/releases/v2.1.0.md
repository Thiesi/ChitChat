# ChitChat v2.1.0

`v2.1.0` is a maintenance release on top of `v2.0.2`. It adds two maintainer-requested features, unobtrusive registration bot protection and a layout that fills the browser on every screen size, and fixes several interface bugs. It applies one forward-only database migration.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). ChitChat remains feature-complete. The features below are specific, concretely requested additions of the kind the maintenance-only policy reserves room for, not a resumption of open-ended roadmap work. See [`docs/roadmap.md`](../roadmap.md).

## Added

- **Registration bot protection** that people don't notice. ([#94](https://github.com/Thiesi/ChitChat/pull/94))
  - A hidden decoy field that only form-filling bots fill in.
  - A minimum time between showing the registration form and submitting it (default 3 seconds).
  - A small proof-of-work puzzle that the browser solves in the background while the person fills in the form (default 16 bits, about a second on a typical device).
  - There is no third-party CAPTCHA, no tracking, and no visible puzzle. The challenge is issued by `GET /api/v1/registration-challenge.php` and is single-use.
- **Registration protection settings.** A new section under **Operational settings** lets a Super-Administrator override the per-IP registration limit (attempts and window), the minimum fill time, and the proof-of-work difficulty. ([#94](https://github.com/Thiesi/ChitChat/pull/94))
  - Empty fields use the server defaults from the environment, so existing `RATE_LIMIT_REGISTRATION_*` configuration keeps working.
  - Changes require privileged step-up and are audited as `system.registration_protection_updated`. Because they tune abuse resistance rather than an installation policy that affects people's data, they do not send every account a policy-change notification.
- **A phone menu.** On narrow screens a **Menu** button in the chat sidebar opens search, direct messages, privacy notifications, account, administration, and sign-out. It shows a dot while privacy notifications are unread. ([#93](https://github.com/Thiesi/ChitChat/pull/93))
- **Full-width pages and an in-field attach button.** ([#93](https://github.com/Thiesi/ChitChat/pull/93))
  - Account, privacy notifications, direct messages, search, administration, moderation, and revision review now fill the browser width.
  - Attaching a file uses a paperclip button inside the message field instead of a separate row.

## Fixed

- **Settings and navigation were unreachable on phones.** The narrow-screen chat layout hid the sidebar footer entirely, so search, direct messages, privacy notifications, account, administration, and sign-out could not be reached from the chat page. The new Menu button restores access. ([#93](https://github.com/Thiesi/ChitChat/pull/93))
- **Checkboxes rendered above their label text**, as on the push-notification "Notify me when I'm mentioned" option and the account-closure confirmation. ([#92](https://github.com/Thiesi/ChitChat/pull/92))

## What to evaluate

Operators staging this release should exercise:

- registering a new account in a browser, confirming it succeeds without any visible challenge, and that the registration form briefly waits for the background check if submitted very quickly after opening it;
- **Operational settings → Registration protection**: overriding a value, confirming the effective values update, and clearing a field to return to the server default;
- the chat page on a phone: the Menu button, its unread-notification dot, and every link in it;
- the account, privacy-notification, direct-message, search, administration, and moderation pages on a wide screen;
- attaching, removing, and sending a file with the paperclip button in rooms and direct messages;
- existing login, MFA, passkey, room, direct-message, attachment, search, moderation, reply, mention, reaction, inspection, export, retention, maintenance, and reverse-proxy SSE behavior remaining unaffected.

## Database changes

Upgrading from `v2.0.2` (or `v2.0.1`/`v2.0.0`) applies this forward-only migration:

- `0023_registration_protection.sql` adds four nullable override columns to `system_settings`: `registration_rate_limit_max_attempts`, `registration_rate_limit_window_seconds`, `registration_min_fill_seconds`, and `registration_proof_of_work_bits`. `NULL` means the server default applies, so behavior after migration matches the configured environment.

Back up PostgreSQL and attachment storage together before any deployment. Rolling back requires restoring a matching pre-upgrade database and attachment backup; there is no down-migration path.

## Upgrade from v2.0.2

1. Stop or drain application writes.
2. Create and verify a complete PostgreSQL-plus-attachment backup set.
3. Preserve `.env` and the existing attachment-storage path.
4. Deploy `v2.1.0` source.
5. Compare `.env` with `.env.example`. Retain existing values; optionally set `REGISTRATION_MIN_FILL_SECONDS` and `REGISTRATION_PROOF_OF_WORK_BITS` to change the server defaults (3 and 16).
6. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   composer maintenance:dry-run
   ```

7. Verify `/health.php`, `/ready.php`, login, registration in a browser, the Operational settings page, room and direct-message history, attachments, and SSE through the production reverse proxy.

Registration now requires a browser with Web Crypto, which every current browser provides over HTTPS. Scripts that register accounts directly through the API must either solve the challenge or run with both checks set to `0`; see `docs/api/authentication.md`. Browsers may hold the previous stylesheets and scripts in cache; a reload picks up the new layout.

## Validation required for publication

The exact merged release commit must pass:

- locked Composer and npm dependency audits;
- PHP lint, JavaScript and stabilization-shell syntax checks, and PHPStan level 8 on PHP 8.2, 8.3, and 8.4;
- the complete PHPUnit suite against PostgreSQL 16 on PHP 8.2, 8.3, and 8.4;
- the full browser journey, including registration through the bot-protection challenge, independently in Chromium, Firefox, and WebKit;
- structural and keyboard accessibility checks in all three engines, including the phone menu;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v2.1.0` tag and stable GitHub release are created.
