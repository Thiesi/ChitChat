# ChitChat v3.5.0

`v3.5.0` gives the web client ChitChat Mobile's new look, and rebuilds push notifications: they're reliable, safer and tied to sign-in. It also adds opt-in alerts for direct messages. API v1 changes are additive. It adds four forward-only database migrations (`0045` to `0048`) and one dependency, so back up before upgrading.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It ships the third batch of additions requested by the ChitChat Mobile client and the first step of the maintainer-approved presentation overhaul, both tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Changed

- **A new look, shared with ChitChat Mobile.** ([#167](https://github.com/Thiesi/ChitChat/issues/167), [#188](https://github.com/Thiesi/ChitChat/pull/188))
  - The default colour scheme is now **Lantern**: warm night ink, persimmon actions and honey for presence. Its display font, Bricolage Grotesque, is self-hosted, never loaded from Google Fonts.
  - New icons, a favicon, a home-screen icon, and a web app manifest, so ChitChat can be installed on phones and desktops.
  - Layouts are unchanged. The other colour schemes (Lounge, Dusk, Ember, Rose, Midnight, Contrast) stay available under Appearance. Every explicit choice is kept.
  - Earlier explicit choices of **Lounge**, the old default, couldn't be stored and therefore move to Lantern. Members who never chose a scheme see a one-time, dismissible note that points to Appearance.

## Added

- **Opt-in alerts for new direct messages.** ([#150](https://github.com/Thiesi/ChitChat/issues/150); [#194](https://github.com/Thiesi/ChitChat/pull/194), [#195](https://github.com/Thiesi/ChitChat/pull/195))
  - They're off by default. Members turn them on under Alerts: "New direct messages".
  - An alert names the sender and never includes message content. A direct message that also mentions you produces one alert, not two.
  - Reading the conversation marks its alerts read. Account-wide alert choices are now visible even in a browser that hasn't turned on push.
- **Data for the upcoming administration redesign.** ([#191](https://github.com/Thiesi/ChitChat/issues/191), [#196](https://github.com/Thiesi/ChitChat/pull/196)) User-list filters and counts (staff, banned, muted, closing), sorting by last sign-in, audit entries for one account, and moderation cases about one person. Staff access rules are unchanged.

## Improved

- **Reliable push delivery.** ([#148](https://github.com/Thiesi/ChitChat/issues/148), [#189](https://github.com/Thiesi/ChitChat/pull/189))
  - Each device is delivered and retried on its own, with bounded backoff, and a device that already received an alert is never sent it again.
  - Alerts expire after 30 minutes (mentions, pings, direct messages) or 6 hours (everything else), so no stale alert arrives days later.
  - Notifications that were already read, or that the person may no longer see, aren't pushed.
  - Push services on non-standard ports now authenticate correctly.
- **Safer push subscriptions.** ([#147](https://github.com/Thiesi/ChitChat/issues/147), [#193](https://github.com/Thiesi/ChitChat/pull/193))
  - Push addresses are validated, and every send is checked and pinned to public addresses, so the server can't be used to reach internal systems.
  - Subscriptions belong to the login session. Signing out removes them, even if the browser is offline at the time.
  - At most 20 devices per account. Pushes carry additive fields that native clients use for channels and de-duplication.

## Fixed

- **The version follows the deployed release.** The environment template no longer pins `APP_VERSION`, and release publication rejects a pinned template. ([#190](https://github.com/Thiesi/ChitChat/issues/190), [#199](https://github.com/Thiesi/ChitChat/pull/199))

## What to evaluate

Operators staging this release should check that:

- the new look appears for members who never chose a scheme, and that existing explicit schemes are kept;
- sign-in, rooms, direct messages, attachments and moderation work as before;
- turning on push in a browser, receiving a mention alert, and signing out (which removes that browser's subscription) all work;
- turning on "New direct messages" alerts a test account about a new direct message.

## Database changes

All four migrations are forward-only:

- `0045_push_delivery_ledger.sql`: per-event and per-device push delivery records (no endpoints, keys or content).
- `0046_push_dispatch_wakeup.sql`: a commit-time wake signal for the optional listener (an empty payload).
- `0047_push_subscription_lifecycle.sql`: session binding, rotation generation and device labels for subscriptions, plus event IDs.
- `0048_direct_message_alerts.sql`: the `direct_message_received` notification kind and preference.

## New dependency

`react/dns` (with its MIT-licensed `react/event-loop`, `react/promise` and `react/cache`) gives push-destination checks a strict DNS time limit. It reads the system's `resolv.conf` and hosts file, and uses no external resolver.

## Operator notes

- **Remove `APP_VERSION` from your `.env`** (recommended), or update it to `3.5.0`. A leftover pin keeps reporting the old version.
- **Push dispatch.** Keep the dispatcher scheduled. The example timer now runs every 15 seconds (it was 30); update an installed timer unit if you want the faster cadence.
- **Optional instant push delivery.** `php bin/dispatch-web-push --listen` wakes on new notifications and typically delivers within a second, with the timer as a safety net. A systemd service is documented in `docs/operations/web-push.md` but not installed automatically: installing it is the maintainer's decision. It needs PHP's `pcntl` extension for clean shutdown.
- **Optional settings:**
  - `WEB_PUSH_PRIVATE_PROVIDERS` is only needed for a push service on a private network (exact origin plus CIDR). Public services, including ntfy.sh, need nothing.
  - `WEB_PUSH_DNS_RESOLV_CONF` overrides the DNS configuration file and is mainly for Windows hosts.
- **Existing push subscriptions keep working.** The first sign-out per account also removes that account's older, unbound browser subscriptions. Browsers that are still in use register again automatically on their next visit.
- Continue backing up PostgreSQL and attachment storage together.

## Upgrade from v3.4.0

1. Back up PostgreSQL and attachment storage together.
2. Deploy `v3.5.0` source. Remove `APP_VERSION` from `.env` (or update it).
3. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```

   `composer migrate` applies `0045` to `0048`.
4. Reload PHP-FPM, and restart the push dispatcher timer, or the listener if you install it.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.5.0`.

Upgrading from before `v3.4.0` also applies that release's migrations (`0040` to `0044`); see its notes.

## Known limitations

Unchanged from `v3.4.0`. In addition:

- Push delivery is at least once and best effort: a worker crash right after a provider accepts an alert can repeat it. Native clients de-duplicate by event.
- The server can't detect a passively expired browser session. Until that browser signs in again, its pushes are discarded by the browser rather than stopped at the server.
- The conversation view, navigation and administration redesigns follow in later releases.
