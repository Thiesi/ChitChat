# ChitChat v3.7.0

> **Everyone will need to sign in again once after this update**, including in the ChitChat app. Guests start guest access again. Accounts, passwords, passkeys, linked providers, recovery keys and conversations are unaffected. **Announce it before upgrading**, using the [ready-to-post text](../operations/session-registry-upgrade.md#ready-to-post-site-announcement).

`v3.7.0` lets people see where they're signed in and sign other sessions out, adds authenticator-app codes as a second sign-in step, and brings the first big part of the Lantern redesign: a new conversation view, one navigation frame on every page, and Activity and You pages in place of the old menus. API v1 changes are additive. It adds two forward-only database migrations (`0051` and `0052`) and one optional set of settings, so back up before upgrading.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It completes the fifth batch of additions requested by the ChitChat Mobile client and continues the maintainer-approved presentation overhaul, both tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Added

- **Where you're signed in.** ([#205](https://github.com/Thiesi/ChitChat/issues/205); [#229](https://github.com/Thiesi/ChitChat/pull/229), [#232](https://github.com/Thiesi/ChitChat/pull/232), [#231](https://github.com/Thiesi/ChitChat/pull/231), [#234](https://github.com/Thiesi/ChitChat/pull/234))
  - Under You, every sign-in is listed: browser or app (for example "Firefox on Windows" or "ChitChat app on Android"), when it signed in and when it was last active. No IP addresses or locations are shown or stored for this.
  - Sign out one session, or all others; signing out all others asks you to confirm your identity first.
  - A session that's signed out elsewhere is told "You were signed out from another device". Its push alerts stop and its live connection closes right away.
- **Authenticator-app codes as a second sign-in step.** ([#204](https://github.com/Thiesi/ChitChat/issues/204), [#236](https://github.com/Thiesi/ChitChat/pull/236))
  - **Setup:** set up an authenticator app under You by scanning a QR code (drawn on the page, never by an outside service) or by typing the key in.
  - **Where codes work:** wherever a passkey does: sign-in, account restoration, confirming your identity and password reset.
  - **Alongside the other methods:** passkeys and recovery codes keep working. An authenticator alone satisfies "two-step sign-in required" for administrators.
  - **Off until set up.** Authenticator codes stay unavailable until the operator chooses where the encryption key lives; see the operator notes.

## Changed

- **A new conversation view.** ([#166](https://github.com/Thiesi/ChitChat/issues/166); [#192](https://github.com/Thiesi/ChitChat/pull/192), [#221](https://github.com/Thiesi/ChitChat/pull/221), [#222](https://github.com/Thiesi/ChitChat/pull/222))
  - **Look:** rooms and direct messages use the Lantern message bubbles, with day headings and one consistent frame for images.
  - **Keyboard:** the message list is a single Tab stop; ↑/↓, Home and End move between messages, and Enter or Shift+F10 opens a message's actions.
  - **Screen readers** get calm announcements, for example "3 new messages" rather than every line. Edits and reactions are read when you reach the message, and the full date and time is part of each message's spoken label.
- **One navigation frame on every page.** ([#168](https://github.com/Thiesi/ChitChat/issues/168); [#224](https://github.com/Thiesi/ChitChat/pull/224), [#230](https://github.com/Thiesi/ChitChat/pull/230))
  - **Navigation:** a side rail on tablets and desktops and a bottom bar on phones (Rooms, Direct, Activity, You), plus Stewarding for staff.
  - **Activity:** the notification bell becomes the Activity page (mark one or all read).
  - **You:** the account menu becomes the You page (picture, appearance, alerts and sounds, Stewarding for staff, and Sign out), at most two steps from anywhere.
- **New icons and a warning colour.** ([#225](https://github.com/Thiesi/ChitChat/issues/225), [#228](https://github.com/Thiesi/ChitChat/pull/228)) Interface icons are shared with the ChitChat app. Warnings use an amber triangle and errors a red octagon, so they're distinguishable without colour.

## Fixed

- **Mentions at the end of a sentence.** "@ada." now mentions Ada. ([#218](https://github.com/Thiesi/ChitChat/issues/218), [#223](https://github.com/Thiesi/ChitChat/pull/223))
- **Readable buttons in every state.** Main and danger buttons keep readable labels on hover and while pressed, in every colour scheme. ([#235](https://github.com/Thiesi/ChitChat/issues/235), [#237](https://github.com/Thiesi/ChitChat/pull/237))

## What to evaluate

Operators staging this release should check that:

- after the upgrade, everyone (including you) has to sign in once, and signing in again works;
- You lists your sessions, and signing one out from another browser shows that browser "You were signed out from another device";
- the conversation view, the side rail or bottom bar, Activity and You all work, including on a phone;
- if you enable authenticator codes, setting one up and signing in with a code work.

## Database changes

Both migrations are forward-only:

- `0051_login_sessions.sql`: the registry of signed-in sessions. **It signs every existing login out once** (account session versions advance and previous push registrations are removed).
- `0052_totp.sql`: encrypted authenticator credentials, pending set-ups, and the optional in-database key.

## Operator notes

- **Announce the one-time sign-out before upgrading.** The ready-to-post text is in [`docs/operations/session-registry-upgrade.md`](../operations/session-registry-upgrade.md).
- **No required configuration changes.** Authenticator codes stay off until you choose a key source:
  - **Recommended:** run `php bin/totp-key generate` in a private terminal. It prints a key and installs nothing. Add the printed `TOTP_ENCRYPTION_KEYS` and `TOTP_ACTIVE_KEY_ID` lines to `.env`, and keep a copy of the keys with your backups, separately protected. Backups then contain only encrypted secrets.
  - **Convenience:** a Super Administrator can switch on "Store the authenticator key inside ChitChat" in admin settings. Backups then contain both the key and the secrets, which suits small or family installations.
  - **Precedence and safety:** a server key always wins. An invalid server key disables authenticator codes only, and protected health reports it. See [`docs/operations/totp.md`](../operations/totp.md), including key rotation.
- **Push:** after everyone signs in again, browsers and apps register for push again by themselves.
- Continue backing up PostgreSQL and attachment storage together.

## Upgrade from v3.6.0

1. Announce the one-time sign-out.
2. Back up PostgreSQL and attachment storage together.
3. Deploy `v3.7.0` source.
4. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```

   `composer migrate` applies `0051` and `0052`.
5. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
6. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.7.0`. Then sign in again.

Upgrading from before `v3.6.0` also applies that release's migrations (`0049` and `0050`); see its release notes.

## Known limitations

Unchanged from `v3.6.0`. In addition:

- The redesign continues: the room and direct-message lists, the phone list-to-conversation flow, the conversation header, sign-in screens, account area and administration follow in later releases.
- If someone starts signing in to another account on a browser and abandons the second step, the earlier account's sign-in stays listed for its owner until they sign it out.
