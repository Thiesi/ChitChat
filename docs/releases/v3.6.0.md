# ChitChat v3.6.0

`v3.6.0` lets administrators set the installation's own icon inside ChitChat, and makes the suggestion lists usable from the keyboard. It adds the server side of signing in to the ChitChat Mobile app (passkeys and browser sign-in, both off until configured) and fixes two sign-in and restoration bugs. API v1 changes are additive. It adds two forward-only database migrations (`0049` and `0050`), so back up before upgrading.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It completes the fourth batch of additions requested by the ChitChat Mobile client, tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Added

- **The installation's own icon, set in ChitChat.** ([#211](https://github.com/Thiesi/ChitChat/issues/211), [#217](https://github.com/Thiesi/ChitChat/pull/217))
  - **Where:** Admin settings, next to the installation name. A Super Administrator uploads one square PNG or WebP image (512–4000 pixels, up to 4 MiB) and picks a background colour.
  - **Before saving:** previews show it as a round phone icon, a rounded-square icon and at real browser-tab size, and nothing changes until you save.
  - **What ChitChat generates:** the browser-tab icon, the home-screen and app icons (logos with transparent edges are fitted as large as safely possible), and `/favicon.ico`.
  - **Storage:** the icon lives in the database, so it survives upgrades and is included in backups. No web-server configuration is needed.
  - **Reset** returns to the ChitChat icon. Changing the icon requires a fresh identity confirmation.
- **Passkeys in the Android app.** ([#145](https://github.com/Thiesi/ChitChat/issues/145), [#201](https://github.com/Thiesi/ChitChat/pull/201)) Once an installation lists the official app builds it trusts (`NATIVE_ANDROID_APPS`), people can use their passkeys in the app for every existing passkey step. It's off by default.
- **Signing in to the Android app through the browser.** ([#146](https://github.com/Thiesi/ChitChat/issues/146), [#210](https://github.com/Thiesi/ChitChat/pull/210))
  - People sign in with Google or Twitch in their browser, explicitly confirm, and return to the app.
  - It also covers creating or restoring an account, linking a provider, re-confirming identity and importing a profile picture, and two-step sign-in still applies.
  - It's off until an installation trusts the app and has HTTPS and a provider configured.
- **How long alerts stay on screen.** ([#212](https://github.com/Thiesi/ChitChat/issues/212), [#214](https://github.com/Thiesi/ChitChat/pull/214)) Alerts now explains that the device decides where notifications appear and how long they stay, with the Windows, macOS and Android settings to change it.

## Improved

- **Keyboard selection in the `@` and `/` lists.** ([#213](https://github.com/Thiesi/ChitChat/pull/213))
  - **The selected entry is now clearly visible:** ↑/↓ moves through the list, and Enter or Tab picks the entry. The selected entry has an accent background and an edge bar in every colour scheme, light and dark, with extra outlines in high-contrast modes.
  - **The list scrolls** to keep the selection in view.
  - **Mouse hover** moves the same highlight.

## Fixed

- **Strict-cookie sign-in no longer loses the browser session.** ([#206](https://github.com/Thiesi/ChitChat/issues/206), [#215](https://github.com/Thiesi/ChitChat/pull/215)) On installations that set `SESSION_COOKIE_SAMESITE=Strict`, a Google or Twitch sign-in could fail with "expired" and sign out a browser that was already signed in. The default `Lax` setting wasn't affected.
- **Restoring a closing account can't clash with closure finalization.** ([#207](https://github.com/Thiesi/ChitChat/issues/207), [#216](https://github.com/Thiesi/ChitChat/pull/216)) A restoration racing the background finalizer could fail with a database error. It now waits in a consistent order and reports honestly if the deadline passed or the account was already closed.

## Documentation

- **NetBSD with rc.d, cron and Apache plus PHP-FPM** ([#208](https://github.com/Thiesi/ChitChat/issues/208), [#209](https://github.com/Thiesi/ChitChat/pull/209)): a new operator guide with ready-to-adapt examples (`docs/operations/netbsd-apache.md`, `deploy/netbsd/`).
- **Windows development** ([#202](https://github.com/Thiesi/ChitChat/issues/202), [#203](https://github.com/Thiesi/ChitChat/pull/203)): the test suite now runs cleanly on Windows.

## What to evaluate

Operators staging this release should check that:

- an administrator can preview, save and reset an installation icon, and that tabs and installed apps pick it up;
- typing `@` and pressing ↓ visibly moves the selection, and Enter inserts the name;
- sign-in, rooms, direct messages, attachments, push and moderation work as before;
- `session.php` reports `capabilities.native_passkey_origins` and `capabilities.native_auth_handoff` as `false` on an installation without app trust.

## Database changes

Both migrations are forward-only:

- `0049_native_auth_transactions.sql`: short-lived records for app sign-in hand-offs (hashes only; inert until configured).
- `0050_installation_icon.sql`: installation icon generations (current plus at most one previous) and the current-icon setting.

## Operator notes

- **No required configuration changes.** Both app features stay off until configured. `NATIVE_ANDROID_APPS` defaults to `[]`.
- **Installation icon:** set it under Admin settings. Uploads need PHP's GD with PNG and WebP support, which ChitChat already uses for image previews. If you previously mapped icon URLs in the web server (`Alias /favicon.svg`, `/assets/app-icons/…`, `/favicon.ico`), remove those mappings after setting the icon in ChitChat, or they keep overriding it.
- **Only when enabling the Android app:**
  - `NATIVE_ANDROID_APPS` with the app's signing-certificate fingerprints;
  - an exact web-server rule so `/.well-known/assetlinks.json` reaches `assetlinks.php`: see `docs/operations/nginx-php-fpm.md`, or the Apache rule in `docs/operations/netbsd-apache.md`;
  - an access-log format without query strings;
  - for browser sign-in, an explicit HTTPS `APP_ORIGIN` and a matching provider callback origin.
- Continue backing up PostgreSQL and attachment storage together. Icon images are in the database dump.

## Upgrade from v3.5.0

1. Back up PostgreSQL and attachment storage together.
2. Deploy `v3.6.0` source.
3. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```

   `composer migrate` applies `0049` and `0050`.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.6.0`.

Upgrading from before `v3.5.0` also applies that release's migrations (`0045` to `0048`) and operator notes; see its release notes.

## Fresh installation

Follow `INSTALL.md`, or `docs/operations/netbsd-apache.md` on NetBSD with Apache.

## Known limitations

Unchanged from `v3.5.0`. In addition:

- The Android app features need ChitChat Mobile's own sign-in support, which hasn't shipped yet. Their final acceptance is a real-device test.
- A mention followed by a full stop (`@ada.`) isn't recognised yet ([#218](https://github.com/Thiesi/ChitChat/issues/218)); the fix follows.
- The conversation view, navigation and administration redesigns follow in later releases.
