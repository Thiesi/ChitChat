# ChitChat v3.0.0

`v3.0.0` is a usability release on top of `v2.4.0`, and the largest change since `v2.0.0`. It reworks how the chat is navigated and adds what people expect from a chat today, such as profile pictures, unread markers, formatting, typing indicators and signing in with Google or Twitch, alongside operator tools such as room deletion and a maintenance lockdown. It is a major version because of its size and the reworked interface; the HTTP API only gains endpoints and fields, so existing clients keep working.

It applies **thirteen forward-only database migrations** (`0025` to `0037`), so upgrading needs a backup first.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). Every change below is a specific, maintainer-requested addition of the kind the maintenance-only policy reserves room for, agreed as one usability plan, not a resumption of open-ended roadmap work. See [`docs/roadmap.md`](../roadmap.md).

## Added

**Getting around**
- **A reworked chat page.** ([#106](https://github.com/Thiesi/ChitChat/pull/106))
  - The sidebar holds only rooms (with an invited, age or privacy marker only where it matters) and recent direct messages with unread counts.
  - A top bar has members, search, notifications and an account menu, and the members list opens as a panel on demand.
  - On phones, the sidebar opens as a drawer, and members and the account menu open as sheets from the bottom.
- **A live room list.** Rooms that are created, renamed or deleted, and rooms you join, leave or are invited to, update in open tabs without a reload. ([#105](https://github.com/Thiesi/ChitChat/pull/105))
- **Unread markers.** Joined rooms with new messages are bold with a count. Opening one shows a **New messages** divider, and a **Jump to latest** button replaces being pulled away from older history. ([#118](https://github.com/Thiesi/ChitChat/pull/118))

**People**
- **Profile pictures and a profile card.** You crop a picture in the browser, and the server stores a freshly encoded 256 × 256 copy with no photo metadata. Clicking any name opens a card with the picture, staff badge, join date and **Send direct message**. ([#107](https://github.com/Thiesi/ChitChat/pull/107), [#112](https://github.com/Thiesi/ChitChat/pull/112))
- **Tab completion for names** in both composers. ([#107](https://github.com/Thiesi/ChitChat/pull/107))
- **Ignoring people in rooms**, from the profile card. Their messages collapse to one line, and their pings, mentions and unread counts go quiet. They are not told, and direct messages keep using blocking. ([#120](https://github.com/Thiesi/ChitChat/pull/120))

**Messages**
- **Formatting and clickable links.** `*bold*`, `_italic_`, `` `code` ``, code blocks and `> ` quotes are supported. Formatting is built as page elements, never HTML. Links open safely in a new tab, with no link previews. ([#117](https://github.com/Thiesi/ChitChat/pull/117))
- **Slash commands** with a `/` suggestion list: `/help`, `/dm`, `/topic` and `/shrug`, beside `/me` and `/ping`. ([#119](https://github.com/Thiesi/ChitChat/pull/119))
- **A typing indicator** in rooms and direct messages. It carries no text, expires within seconds, and can be turned off on the Account page. Turning it off works both ways. ([#122](https://github.com/Thiesi/ChitChat/pull/122), [#124](https://github.com/Thiesi/ChitChat/pull/124))
- **Pings that cannot be missed.** Each `/ping` is a private notice in the room for its sender and target, reaches people who are offline through notifications and push, and comes with optional sounds and a tab-title counter. ([#108](https://github.com/Thiesi/ChitChat/pull/108), [#109](https://github.com/Thiesi/ChitChat/pull/109))

**Look and feel**
- **Colour schemes**: Lounge, Dusk, Ember, Rosé, Midnight (OLED black) and High contrast, each light and dark, chosen per device. ([#110](https://github.com/Thiesi/ChitChat/pull/110))
- **A per-account date and time format**, which follows the account to every device. ([#110](https://github.com/Thiesi/ChitChat/pull/110))

**Accounts**
- **Signing in and signing up with Google or Twitch.** ([#114](https://github.com/Thiesi/ChitChat/pull/114), [#115](https://github.com/Thiesi/ChitChat/pull/115), [#116](https://github.com/Thiesi/ChitChat/pull/116), [#121](https://github.com/Thiesi/ChitChat/pull/121))
  - It uses OpenID Connect with PKCE, state and nonce, and asks only for the `openid` scope. ChitChat stores an account identifier, never an email address, and verifies every token itself.
  - Accounts created through a provider have no password until they set one. They confirm sensitive actions by signing in with the provider again, or with a passkey.
  - A connected account can opt in to using its provider picture.
  - Each provider is off until configured.
- **A Password card** on the Account page, to change the password or set a first one. ([#115](https://github.com/Thiesi/ChitChat/pull/115))

**Operators**
- **Two-stage room deletion.** Rooms can be restored during a configurable grace period, and moderation evidence is kept. ([#111](https://github.com/Thiesi/ChitChat/pull/111))
- **A maintenance lockdown for Super-Administrators**, with a sign-in message and a live banner. ([#113](https://github.com/Thiesi/ChitChat/pull/113))

## Changed

- "Privacy notifications" is now "Notifications". ([#106](https://github.com/Thiesi/ChitChat/pull/106))
- Message bodies are `<div>` elements instead of `<p>`, so they can hold quotes and code blocks. ([#117](https://github.com/Thiesi/ChitChat/pull/117))

## Fixed

- The Operational settings layout; administration and moderation pages now use the full width. ([#104](https://github.com/Thiesi/ChitChat/pull/104))
- Slash commands no longer break across lines in notifications. Shift+Tab in the composer no longer picks an @mention. Message avatars take their colour from the account rather than the name. ([#104](https://github.com/Thiesi/ChitChat/pull/104))

`CHANGELOG.md` lists every change in detail.

## What to evaluate

Operators staging this release should exercise:

- the chat page on a wide screen and a phone: rooms, the drawer, the members panel, the account menu, notifications, and every colour scheme in light and dark;
- unread counts, the New messages divider and Jump to latest across two browsers;
- formatting, links, slash commands, the typing indicator (including turning it off), pings to someone offline, and ignoring someone;
- profile pictures (the PHP GD extension with WebP support must be installed, otherwise initials stay);
- if configured: Google or Twitch sign-in, sign-up without a password, step-up and restoration through the provider, and the picture button;
- room deletion and restoration, and the maintenance lockdown;
- existing login, MFA, passkey, registration, direct-message, attachment, search, moderation, export, retention, maintenance and reverse-proxy SSE behaviour remaining unaffected.

## Database changes

Thirteen forward-only migrations, applied by `composer migrate`:

| Migration | Adds |
|---|---|
| `0025_rooms_changed_event.sql` | the `rooms_changed` realtime event |
| `0026_room_pings.sql` | stored pings and the `pinged` notification |
| `0027_date_time_preferences.sql` | per-account date and time format |
| `0028_room_deletion.sql` | room deletion, its grace period and notifications |
| `0029_avatars.sql` | profile pictures |
| `0030_maintenance_lockdown.sql` | the lockdown settings |
| `0031_sign_in_providers.sql` | connected Google/Twitch accounts and cached signing keys |
| `0032_password_less_accounts.sql` | `users.has_password` |
| `0033_room_reads.sql` | read positions for unread markers (existing members start fully read) |
| `0034_user_ignores.sql` | ignored people |
| `0035_avatar_imports.sql` | a provider picture waiting for the crop step |
| `0036_typing_event.sql` and `0037_share_typing.sql` | the typing event and its setting |

There is no going back without the backup: older source must not be pointed at the migrated database.

## Upgrade from v2.4.0

1. Stop or drain application writes.
2. Create and verify a complete PostgreSQL-plus-attachment backup set.
3. Preserve `.env` and the existing attachment-storage path. Profile pictures are stored there too.
4. Deploy `v3.0.0` source.
5. Compare `.env` with `.env.example`. The new variables are all optional:
   - `OIDC_REDIRECT_ORIGIN`;
   - `GOOGLE_OIDC_CLIENT_ID` and `GOOGLE_OIDC_CLIENT_SECRET`;
   - `TWITCH_OIDC_CLIENT_ID` and `TWITCH_OIDC_CLIENT_SECRET`.

   Leave them out to keep provider sign-in off. `INSTALL.md` explains how to register the redirect address with Google and Twitch.
6. For profile pictures, install the PHP GD extension with WebP support (for example `php-gd`).
7. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   composer maintenance:dry-run
   ```

8. Verify:
   - `/health.php`, `/ready.php`, login and sending a message;
   - the room list and unread counts;
   - uploading a profile picture;
   - SSE through the production reverse proxy, including the typing indicator between two browsers.

Browsers may hold the previous stylesheets and scripts in cache; a reload picks up the new interface.

## Validation required for publication

The exact merged release commit must pass:

- locked Composer and npm dependency audits;
- PHP lint, JavaScript and stabilization-shell syntax checks, JavaScript unit tests, and PHPStan level 8 on PHP 8.2, 8.3 and 8.4;
- the complete PHPUnit suite against PostgreSQL 16 on PHP 8.2, 8.3 and 8.4;
- the full browser journey independently in Chromium, Firefox and WebKit. This includes a local mock OpenID provider for Google sign-in, sign-up, step-up, restoration and the picture import, and two-browser checks of unread markers, ignoring, slash commands and typing;
- structural and keyboard accessibility checks in all three engines, and axe-core checks of both themes in Chromium;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v3.0.0` tag and stable GitHub release are created.

## Known limitations

Unchanged from `v2.0.0` (see its [known limitations](v2.0.0.md#known-limitations)), plus the following:

- Read positions and the typing indicator do not sync between your own open devices immediately. Another device catches up on its next room-list refresh.
- Confirming a sensitive action through Twitch relies on Twitch's confirmation screen, because Twitch does not report when its sign-in happened (see `INSTALL.md`).
