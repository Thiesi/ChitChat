# ChitChat v2.3.0

`v2.3.0` is a maintenance release on top of `v2.2.0`. It adds a light theme with a System / Light / Dark setting. It applies no database migration.

This is an in-place application upgrade from `v2.2.0`. Operators may deploy `v2.3.0` without a database backup/restore cycle beyond ordinary operational practice. Upgrading from an earlier release also applies that release's migrations; see its notes.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). ChitChat remains feature-complete. The addition below is a specific, concretely requested change of the kind the maintenance-only policy reserves room for, not a resumption of open-ended roadmap work. See [`docs/roadmap.md`](../roadmap.md).

## Added

- **A light theme and a Theme setting.** ([#99](https://github.com/Thiesi/ChitChat/pull/99))
  - **Where:** the chat sidebar (inside the Menu on phones) and a new **Appearance** card on the account page, each with System, Light, and Dark.
  - **Default:** follows the device's light or dark setting, and keeps following it when that setting changes.
  - **Persistence:** an explicit choice is saved on the device, applies before the page paints, and is kept in step across open tabs. Nothing is stored on the server.
  - **Colors:** every color is now a theme token. The dark theme looks as before, and the light theme meets WCAG AA contrast.

## What to evaluate

Operators staging this release should exercise:

- the Theme setting in the chat sidebar and on the account page: choosing Light and Dark, reloading, and returning to System;
- with System selected, switching the device between light and dark mode;
- the light theme across chat, direct messages, search, account, notifications, administration, and moderation pages;
- existing login, MFA, passkey, registration, room, direct-message, attachment, search, moderation, reply, mention, reaction, inspection, export, retention, maintenance, and reverse-proxy SSE behavior remaining unaffected.

## Database changes

None. `v2.3.0` applies no migration.

## Upgrade from v2.2.0

1. Stop or drain application writes (optional for a release with no migration, but recommended).
2. Deploy `v2.3.0` source.
3. Compare `.env` with `.env.example`; no new variables were introduced.
4. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   ```

5. Verify `/health.php`, `/ready.php`, login, and the Theme setting.

Browsers may hold the previous stylesheets and scripts in cache; a reload picks up the new theme support.

## Validation required for publication

The exact merged release commit must pass:

- locked Composer and npm dependency audits;
- PHP lint, JavaScript and stabilization-shell syntax checks, and PHPStan level 8 on PHP 8.2, 8.3, and 8.4;
- the complete PHPUnit suite against PostgreSQL 16 on PHP 8.2, 8.3, and 8.4;
- the full browser journey, including the theme setting, independently in Chromium, Firefox, and WebKit;
- structural and keyboard accessibility checks in all three engines, and axe-core checks of both themes in Chromium;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v2.3.0` tag and stable GitHub release are created.
