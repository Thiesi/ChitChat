# ChitChat v2.0.2

`v2.0.2` is a bug-fix release on top of `v2.0.1`. It adds no new feature and applies no database migration. It makes the locked dependencies installable on every supported PHP version again, and fixes chat layout and message-highlight bugs found while stabilizing the browser test suite.

This is an in-place application upgrade from `v2.0.1` (or `v2.0.0`). There is no new migration to apply; operators may deploy `v2.0.2` without a database backup/restore cycle beyond ordinary operational practice.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). ChitChat remains feature-complete: `v2.0.2` is bug-fix work of the kind the project's maintenance-only policy reserves room for, not a resumption of open-ended roadmap work. See [`docs/roadmap.md`](../roadmap.md).

## Fixed

- **The locked dependencies could not be installed on PHP 8.2 or 8.3.** ChitChat requires PHP `^8.2`, but since `v2.0.0` the lock pinned `symfony/options-resolver` `v8.1.0` (pulled in by `minishlink/web-push`), which requires PHP 8.4.1 or newer. `composer install` from the lock therefore failed on PHP 8.2 and 8.3. CI only tested PHP 8.4, so this went unnoticed. The lock now resolves against a PHP 8.2 platform (`config.platform.php`), which selects `symfony/options-resolver` `v7.4.8`, and CI runs static analysis and the PHPUnit suite on PHP 8.2, 8.3, and 8.4. ([#85](https://github.com/Thiesi/ChitChat/pull/85))
- **The room-chat composer drifted below the fold.** The chat page grew with the conversation instead of scrolling the message list, so with any longer history the composer, and the newest messages, sat below the bottom of the window. The chat page is now exactly one viewport tall: only the message list scrolls and the composer always stays in view. Reading position is preserved when the list updates, and **Load older** keeps the same messages in view. ([#89](https://github.com/Thiesi/ChitChat/pull/89))
- **The direct-message composer drifted below the fold in the same way.** The conversation now has a bounded height, so its message list scrolls and the composer stays at its bottom. The privacy notice above it keeps its full size, and on screens tall enough to fit everything the page is exactly one viewport tall. ([#90](https://github.com/Thiesi/ChitChat/pull/90))
- **Reply, search, and notification highlights disappeared.** Clicking a reply preview, or following a search result or mention-notification link, highlighted the target message, but any new message, edit, reaction, or realtime update re-rendered the list and silently removed the highlight. The highlight now survives re-renders, in rooms and direct messages. ([#86](https://github.com/Thiesi/ChitChat/pull/86))

## Maintenance

These changes do not affect a running installation:

- CI runs PHP static checks and PHPUnit on PHP 8.2, 8.3, and 8.4, and publication validation requires each version's result by name. ([#85](https://github.com/Thiesi/ChitChat/pull/85))
- The browser suite is now served through Nginx and PHP-FPM, as in production; is safe to retry; and recovers automatically from a single failed attempt. It previously failed on its first attempt in about a quarter of CI runs for reasons unrelated to the code under test. ([#83](https://github.com/Thiesi/ChitChat/pull/83), [#86](https://github.com/Thiesi/ChitChat/pull/86), [#87](https://github.com/Thiesi/ChitChat/pull/87), [#88](https://github.com/Thiesi/ChitChat/pull/88))
- The README gained a banner and social preview image.

## What to evaluate

Operators staging this release should exercise:

- `composer install --no-dev --classmap-authoritative` from the lock on the PHP version the installation runs, including PHP 8.2 or 8.3;
- a room and a direct-message conversation with a long history, at a small window height and on a phone, confirming the composer stays reachable without scrolling past the history;
- scrolling up in a busy room, confirming new messages, reactions, and edits do not move the reading position, and that **Load older** keeps the current messages in view;
- following a reply preview, a search result, and a mention notification, confirming the target message stays highlighted while new messages arrive;
- existing login, MFA, passkey, room, direct-message, attachment, search, moderation, reply, mention, reaction, inspection, export, retention, maintenance, and reverse-proxy SSE behavior remaining unaffected.

## Database changes

None. `v2.0.2` applies no migration.

## Upgrade from v2.0.1

1. Stop or drain application writes (optional for a bug-fix release with no migration, but recommended).
2. Deploy `v2.0.2` source.
3. Compare `.env` with `.env.example`; no new variables were introduced.
4. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   ```

5. Verify `/health.php`, `/ready.php`, password login, MFA login when enabled, and the Administrator system-status page.

Browsers may hold the previous stylesheets and scripts in cache; a reload picks up the new layout.

## Fresh installation

Follow `INSTALL.md`. PHP 8.2, 8.3, and 8.4 are supported, and the locked dependencies now install on each of them.

## Validation required for publication

The exact merged release commit must pass:

- locked Composer and npm dependency audits;
- PHP lint, JavaScript and stabilization-shell syntax checks, and PHPStan level 8 on PHP 8.2, 8.3, and 8.4;
- the complete PHPUnit suite against PostgreSQL 16 on PHP 8.2, 8.3, and 8.4;
- the full two-session release journey independently in Chromium, Firefox, and WebKit;
- structural and keyboard accessibility checks in all three engines;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v2.0.2` tag and stable GitHub release are created.
