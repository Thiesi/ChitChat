# ChitChat v3.8.0

`v3.8.0` continues the Lantern redesign with the room and direct-message lists and new sign-in screens. It lets moderators require a new username for an offensive name, and adds two settings administrators choose inside ChitChat: preset installation icons and a seasonal decoration for the sign-in page. API v1 changes are additive. It adds three forward-only database migrations (`0053` to `0055`) and needs no configuration changes, so back up before upgrading. **Unlike `v3.7.0`, nobody is signed out.**

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It continues the maintainer-approved presentation overhaul and adds maintainer-approved moderation and administration features, all tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Added

- **Require a new username.** ([#164](https://github.com/Thiesi/ChitChat/issues/164); [#243](https://github.com/Thiesi/ChitChat/pull/243), [#251](https://github.com/Thiesi/ChitChat/pull/251))
  - Global Moderators and above can require a new username for an offensive name, from the profile card or from a person report (which it resolves). A reason is required and shown to the person.
  - The name is replaced at once, everywhere it shows, by a neutral name such as `member-k7q2xm`. The person can still read and sign in (also with their previous name) but chooses a new name before writing again.
  - The removed name stays reserved while the change is pending and for a period after the new name is chosen, set in Operational settings (**Username reservation in days**, default 365; 0 releases it as soon as the new name is chosen).
  - For app developers: capability `moderated_username_change`, `403 username_change_required`, `POST /api/v1/account/username.php`, and the SSE event `user_renamed`. See [`docs/api/username-change.md`](../api/username-change.md).
- **For app developers, also additive:** `session.php` → `sign_in_decoration`, and the profile card's `moderation.everywhere` gains `can_require_username_change` and `username_change_required`.
- **Installation icon presets.** ([#226](https://github.com/Thiesi/ChitChat/issues/226), [#241](https://github.com/Thiesi/ChitChat/pull/241)) Administrators can pick a ready-made icon, or an initial that follows the installation's name, instead of uploading one.
- **A seasonal decoration on the sign-in page.** ([#242](https://github.com/Thiesi/ChitChat/issues/242); [#249](https://github.com/Thiesi/ChitChat/pull/249), [#252](https://github.com/Thiesi/ChitChat/pull/252)) A Super-Administrator chooses None, Winter, Spring or Celebration under Operational settings, with a live preview. It shows only on the sign-in page and is off by default.
- **An accessibility statement and a way to report problems.** ([#219](https://github.com/Thiesi/ChitChat/issues/219), [#255](https://github.com/Thiesi/ChitChat/pull/255)) [`docs/accessibility.md`](../accessibility.md) describes what the web client supports and how it is tested, and an "Accessibility problem" form makes it easy to tell us when something gets in the way.

## Changed

- **Room and direct-message lists.** ([#168](https://github.com/Thiesi/ChitChat/issues/168), [#239](https://github.com/Thiesi/ChitChat/pull/239), [#257](https://github.com/Thiesi/ChitChat/pull/257))
  - On desktops the lists sit in a pane beside the conversation; on tablets they open over it; on phones the list and the conversation are separate screens with a Back button.
  - On phones nothing is opened (or marked read) behind the list until you choose a room or conversation.
  - Conversation headers show who is here; on phones the direct-message header stays on one row, with Report and Block under "More actions".
  - The rail's Direct tab shows unread direct messages.
- **New sign-in screens.** ([#169](https://github.com/Thiesi/ChitChat/issues/169), [#246](https://github.com/Thiesi/ChitChat/pull/246))
  - The installation's own icon and name lead the page ("on ChitChat" is added when the installation has another name), and the card greets you with "Welcome back" or "Make yourself at home".
  - Every sign-in path keeps working as before: password, Google or Twitch, passkeys, authenticator codes, recovery codes, password reset and account restoration.
  - A missing tick on the community rules is explained next to the box.

## Fixed

- **"Signed out from another device" always shows** on the sign-in screen, and is announced to screen readers, even when other requests end at the same moment. ([#246](https://github.com/Thiesi/ChitChat/pull/246))
- **Navigation tabs with unread counts** are named with their visible label first, so voice-control users can say what they see. ([#257](https://github.com/Thiesi/ChitChat/pull/257))
- **Two staff members acting on each other at the same moment** no longer risk a failed request. ([#248](https://github.com/Thiesi/ChitChat/issues/248), [#253](https://github.com/Thiesi/ChitChat/pull/253))

## What to evaluate

Operators staging this release should check that:
- the Rooms and Direct lists, and moving between list and conversation, work on a desktop, a tablet-sized window and a phone;
- signing in, registering (including the rules box) and restoring an account work on the new screens;
- Operational settings shows the icon presets, the sign-in decoration and the username reservation period, and that changes apply;
- requiring a new username from a profile card replaces the name, pauses writing for that person, and that choosing a new name restores it.

## Database changes

All three migrations are forward-only:
- `0053_installation_icon_presets.sql`: preset and initial icon choices.
- `0054_username_change.sql`: required username changes, name reservations and the reservation setting. It adds or replaces CHECK constraints on `users`, `account_notifications`, `realtime_events` and `moderation_cases`, and builds a partial index on account notifications. Each of these briefly locks its table and scans it, so on a large installation, requests touching those tables wait until the migration finishes. Run it with the site's writes drained, as in the upgrade steps below.
- `0055_sign_in_decoration.sql`: the sign-in decoration setting.

## Operator notes

- **No configuration changes.** The new settings are chosen in Operational settings.
- **Refreshed operator documentation:** `INSTALL.md`, `docs/operations/maintenance.md` and the NetBSD guide are brought up to date (authenticator key setup, image support, scheduling, step-up actions). The manual accessibility review is now an optional checklist, not a release gate.
- **Nobody is signed out** by this upgrade.
- Authenticator codes (from `v3.7.0`) stay off until you choose a key source; see [`docs/operations/totp.md`](../operations/totp.md).
- Continue backing up PostgreSQL and attachment storage together.

## Upgrade from v3.7.0

1. Stop writes as for earlier upgrades, and back up PostgreSQL and attachment storage together.
2. Deploy `v3.8.0` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` applies `0053`, `0054` and `0055`.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.8.0`.

Upgrading from before `v3.7.0` also applies that release's migrations (`0051` and `0052`) and its one-time sign-out; read its release notes first.

## Known limitations

Unchanged from `v3.7.0`. In addition:
- The redesign continues: Activity and search lists, You, Stewarding and administration, and a final sweep follow in later releases.
- Below 320 CSS pixels (for example 200% zoom on a small phone) some titles are cut short and the message box is cramped ([#254](https://github.com/Thiesi/ChitChat/issues/254)).
- Push alerts already shown on a device before a name was replaced can't be recalled, and a literal "@OldName" typed inside existing messages stays as written.
