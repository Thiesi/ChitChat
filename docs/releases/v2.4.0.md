# ChitChat v2.4.0

`v2.4.0` is a maintenance release on top of `v2.3.0`. It adds an emoji picker to the composers and gives the interface a warmer, more distinctive look. It applies no database migration.

This is an in-place application upgrade from `v2.3.0`. Operators may deploy `v2.4.0` without a database backup/restore cycle beyond ordinary operational practice. Upgrading from an earlier release also applies that release's migrations; see its notes.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). ChitChat remains feature-complete. The changes below are specific, concretely requested additions of the kind the maintenance-only policy reserves room for, not a resumption of open-ended roadmap work. See [`docs/roadmap.md`](../roadmap.md).

## Added

- **An emoji picker in the composers.** ([#101](https://github.com/Thiesi/ChitChat/pull/101))
  - A smiley button inside the room and direct-message fields opens a searchable picker of 240 common emoji in six categories, with a **Recently used** row saved on the device.
  - Emoji are inserted at the caret, and the picker is fully keyboard operable: a single tab stop, arrow keys, and Escape.
  - It needs no third-party code. Message reactions keep their fixed set of six.

## Changed

- **A warmer, more distinctive interface.** ([#102](https://github.com/Thiesi/ChitChat/pull/102))
  - New ivory/teal (light) and ink/mint (dark) themes.
  - An illustrated welcome screen beside the sign-in card.
  - Decorative speaker initials beside messages. They are hidden from assistive technology, since the speaker's name is already announced.
  - Quieter navigation, and cohesive room and direct-message composers.
  - The typography and shared styling carry through the account, search, moderation, and administration pages. Operator-configured names and every existing feature are preserved.

## Fixed

- Replies and the composer no longer overflow on narrow screens. ([#102](https://github.com/Thiesi/ChitChat/pull/102))
- An empty conversation no longer misplaces its content in the chat layout. ([#102](https://github.com/Thiesi/ChitChat/pull/102))

## What to evaluate

Operators staging this release should exercise:

- the sign-in screen, chat, direct messages, account, search, moderation, and administration pages in both the light and dark themes, on a wide screen and a phone;
- the emoji picker in a room and a direct message: searching, inserting at the caret, the recently used row, and keyboard use;
- replies, long usernames, and empty conversations on a narrow screen;
- existing login, MFA, passkey, registration, room, direct-message, attachment, search, moderation, reply, mention, reaction, inspection, export, retention, maintenance, and reverse-proxy SSE behavior remaining unaffected.

## Database changes

None. `v2.4.0` applies no migration.

## Upgrade from v2.3.0

1. Stop or drain application writes (optional for a release with no migration, but recommended).
2. Deploy `v2.4.0` source.
3. Compare `.env` with `.env.example`; no new variables were introduced.
4. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   ```

5. Verify `/health.php`, `/ready.php`, login, and sending a message with an emoji.

Browsers may hold the previous stylesheets and scripts in cache; a reload picks up the new interface.

## Validation required for publication

The exact merged release commit must pass:

- locked Composer and npm dependency audits;
- PHP lint, JavaScript and stabilization-shell syntax checks, and PHPStan level 8 on PHP 8.2, 8.3, and 8.4;
- the complete PHPUnit suite against PostgreSQL 16 on PHP 8.2, 8.3, and 8.4;
- the full browser journey, including the emoji picker and the presentation checks, independently in Chromium, Firefox, and WebKit;
- structural and keyboard accessibility checks in all three engines, and axe-core checks of both themes in Chromium;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v2.4.0` tag and stable GitHub release are created.
