# ChitChat v1.0.0-rc.1

`v1.0.0-rc.1` is the first release candidate of the clean ChitChat reconstruction. It is intended for controlled evaluation and deployment rehearsal, not yet as an unconditional production recommendation.

## What to evaluate

Operators should exercise the complete workflow on infrastructure resembling the intended deployment:

- first-account bootstrap and role recovery procedures;
- registration enabled and disabled;
- public, unlisted, private, and age-restricted rooms;
- reconnect behavior through the actual reverse proxy;
- multiple simultaneous SSE connections relative to the configured PHP worker pool;
- upload limits in PHP and the reverse proxy;
- attachment storage permissions, backup, restore, and orphan cleanup;
- direct-message privacy disclosure and the chosen administrative-inspection policy;
- retention settings and maintenance dry runs;
- browser behavior outside Chromium, especially current Firefox and Safari releases.

## Installation

Follow `INSTALL.md`. The web server document root must be `public/`, and the attachment directory must be writable by PHP but inaccessible directly through the web server.

For production-like evaluation:

```sh
composer install --no-dev --classmap-authoritative
composer migrate
composer maintenance:dry-run
```

The Node and Playwright packages are development and CI dependencies only; deployed browser clients do not require Node.js.

## Upgrade from v1 development snapshots

Back up PostgreSQL and attachment storage together before applying migrations. Preserve the installation's `.env`; compare it with `.env.example` rather than replacing it. `APP_VERSION` is informational and may be omitted to use the release default.

After deployment:

```sh
composer migrate
composer maintenance:dry-run
```

Verify `/ready.php`, sign in, load room history, upload and download a small allowed file, exchange a direct message, and inspect the audit log.

## Legacy snapshot

The incomplete `v0.10.25` snapshot is a reference artifact, not a supported predecessor. There is no automated schema or content migration from it to v1.

## Privacy notice

Direct messages are stored as ordinary PostgreSQL records and are not end-to-end encrypted. Administrative inspection is enabled for Super-Administrators by default, requires a reason, and audits every returned page. Operators must make this policy visible to users and should disable inspection if it is not required.

## Known limitations

- single application-server target;
- PostgreSQL only;
- text-only direct messages;
- no user blocking or message editing;
- maintenance must be scheduled by the operator;
- Chromium release smoke coverage only;
- release candidate, with compatibility changes still possible before `1.0.0`.

Detailed changes are listed in `CHANGELOG.md`.
