# ChitChat v3.14.0

`v3.14.0` closes three privacy gaps in direct messages and file downloads. It adds a "Report an accessibility problem" link that operators can point at themselves. Screen readers are now interrupted only by errors. Links to rooms and files that are gone say so. The web client gets a round of polish. It applies **one forward-only database migration** (`0061`), so back up before upgrading. **For app developers, two error codes change for callers outside a conversation**, and the API gains additions (see below). Nobody is signed out.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It contains maintainer-approved privacy, accessibility and presentation work, tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Security and privacy

- **Deleted direct-message attachments can't be detected from outside.** ([#356](https://github.com/Thiesi/ChitChat/issues/356), [#359](https://github.com/Thiesi/ChitChat/pull/359)) Someone who isn't in a conversation used to get "deleted" for a deleted attachment but "not found" for one that never existed, which revealed that it had existed. Now both answers are identical. Participants still see "deleted".
- **Editing or deleting a direct message reveals nothing to outsiders.** ([#360](https://github.com/Thiesi/ChitChat/issues/360), [#362](https://github.com/Thiesi/ChitChat/pull/362)) Before, an outsider got a different error depending on whether a message number didn't exist, belonged to someone else's conversation, or had been deleted. Message numbers are sequential, so that revealed how many direct messages existed and how many were deleted, though never their content. Now every such request gets the same "not found". The sender and recipient are unchanged.
- **Room links no longer join guests silently.** ([#354](https://github.com/Thiesi/ChitChat/pull/354)) Opening a link to a public room as a guest used to join it straight away. Now the guest sees the room in the list and joins with their own click. Message and ping links had the same gap and are fixed too.

These follow [#326](https://github.com/Thiesi/ChitChat/issues/326) in `v3.11.0`, which did the same for rooms.

## Added

- **"Report an accessibility problem".** ([#219](https://github.com/Thiesi/ChitChat/issues/219), [#368](https://github.com/Thiesi/ChitChat/pull/368), [#371](https://github.com/Thiesi/ChitChat/pull/371), [#374](https://github.com/Thiesi/ChitChat/pull/374))
  - **Where it appears:** a link in the page footer, also on the sign-in screens, and on You.
  - **Where it leads:** by default, the ChitChat project's accessibility form on GitHub. A Super-Administrator can point it at their own `https:` page or `mailto:` address, or switch it off, in Operational settings › Accessibility feedback.
  - **The hint:** the link says where it goes, for example "(opens GitHub)", the site's name, or "(email)".
  - **The statement:** the [accessibility statement](../accessibility.md) is rewritten to claim only what the test suites check, and it lists the known gaps plainly. The GitHub form also asks whether the problem is in the web client or ChitChat Mobile.
- **Lock-manager waits on System status and in `/metrics.php`.** ([#365](https://github.com/Thiesi/ChitChat/issues/365), [#373](https://github.com/Thiesi/ChitChat/pull/373)) A point sample of database connections waiting on PostgreSQL's lock manager, shown as a neutral number. See [Lock-manager waits](../operations/observability.md#lock-manager-waits).

## Changed

- **Only errors interrupt screen readers.** ([#369](https://github.com/Thiesi/ChitChat/issues/369), [#372](https://github.com/Thiesi/ChitChat/pull/372)) Notices like "Attachment uploaded." used to be announced as urgently as errors. Now they're announced politely, and only errors interrupt.
- **Links to rooms and files that are gone say so.** ([#334](https://github.com/Thiesi/ChitChat/issues/334), [#354](https://github.com/Thiesi/ChitChat/pull/354), [#363](https://github.com/Thiesi/ChitChat/pull/363), [#366](https://github.com/Thiesi/ChitChat/pull/366))
  - A plain link to a room (`/?room_id=N`) now opens that room; before, the room in the link was ignored.
  - A room that's gone, or that you can't see, says "This room isn't available any more." at once, instead of after a wait.
  - A file that's gone says "This file isn't available any more." and shows its name as plain text, instead of opening raw error text.
  - These notices are neutral and don't cover the header.
- **The mention badge follows the server.** ([#355](https://github.com/Thiesi/ChitChat/pull/355)) A room's "@" uses the server's own mention count, so it's right on every device. It clears when you read the room and updates live when someone mentions you elsewhere.
- **Polish.** ([#352](https://github.com/Thiesi/ChitChat/pull/352), [#358](https://github.com/Thiesi/ChitChat/pull/358), [#366](https://github.com/Thiesi/ChitChat/pull/366))
  - The message box starts one line tall, grows as you type up to a limit, has no resize grip and shows one focus ring.
  - Rooms and Direct now share the same composer layout on phones.
  - The keyboard hint is hidden on touch screens.
  - Long room names are cut to two lines.
  - Phones get tidier badges and sign-in band, and the sign-up form fits on very narrow screens.
- **The footer** reads "Powered by ChitChat", without the exclamation mark. ([#370](https://github.com/Thiesi/ChitChat/pull/370))

## For app developers

**Changed error codes**, only for a signed-in caller who isn't a participant in the direct message:
- Downloading a **deleted** DM attachment (`/api/v1/direct-messages/attachments/download.php`) now answers `404 attachment_not_found`, the same as for an attachment that never existed. Before, it was `410 attachment_deleted`.
- Editing or deleting a DM (`/api/v1/direct-messages/edit.php`, `delete.php`) now answers `404 message_not_found` for every message ID. Before, it was `403 message_author_required` for someone else's message and `409 message_already_deleted` for a deleted one. The sender and recipient still get those codes.

**Additions:**
- `HEAD` is accepted on `/api/v1/attachments/download.php` and `/api/v1/direct-messages/attachments/download.php`. It runs the same checks and returns the same status and headers as `GET`, without a body, and it never opens the file. It's a cheap "is this file still there" check. A `HEAD` response has no body, so it can't carry the error code; use `GET` when you need the code.
- Every `405 method_not_allowed` now includes an `Allow` header.
- `GET /api/v1/session.php` gains a public `accessibility_feedback`: `{"url": "…"}`, or `null` when it's switched off. It's present for signed-out callers and guests too. The URL is already resolved, so it's the project's form unless the operator set their own. See [Session](../api/session.md).
- `GET` and `POST /api/v1/admin/settings/accessibility-feedback/…` read and set the destination. These are Super-Administrator only, and updating needs step-up. See [System settings](../api/system-settings.md#accessibility-feedback).
- System status adds `database.lock_manager_waits` and `database.lock_manager_waits_scope`, and `/metrics.php` adds `chitchat_database_lock_manager_waits`.

A client that treats 404 and 410 as "not available" needs nothing.

## What to evaluate

Operators staging this release should check that:
- after the upgrade the footer shows "Report an accessibility problem (opens GitHub)", including signed out, and Operational settings › Accessibility feedback can change or switch it off;
- a link to a room you can't see says "This room isn't available any more.";
- members of a direct message can still edit and delete their own messages.

## Database changes

- `0061_accessibility_feedback.sql` adds two columns to `system_settings`: `accessibility_feedback_enabled` (default true) and `accessibility_feedback_url` (null, which means the project's form). A CHECK constraint allows only `https://` and `mailto:` addresses. The table has a single row, so this is quick.

## Operator notes

- **Back up first:** `0061` is a forward-only migration. Back up PostgreSQL and attachment storage together, and don't point older source at the migrated database.
- **After upgrading:** every installation shows the accessibility link, leading to the ChitChat project's form on GitHub. Point it at your own page or address, or switch it off, in Operational settings.
- **No configuration changes**, and **nobody is signed out**.

## Upgrade from v3.13.0

1. Stop or drain application traffic (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
2. Deploy `v3.14.0` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` applies `0061`.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.14.0` and an `accessibility_feedback` object.

Upgrading from before `v3.10.0` also applies that release's migrations (`0059` and `0060`); read its release notes first.

## Fresh installation

Follow `INSTALL.md`, or `docs/operations/netbsd-apache.md` on NetBSD with Apache.

- structural, keyboard and per-screen axe-core accessibility checks in all three engines, and the deeper both-theme accessibility gate in Chromium;
- the dedicated first-class backup rehearsal;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

Publication validation checks those named results on the exact 40-character merge commit before the annotated `v3.14.0` tag and stable GitHub release are created.
