# ChitChat v3.13.0

`v3.13.0` completes the web client's redesign sweep (Lantern stage S7). The browser's own pop-up boxes are replaced throughout. You can leave a room from the web. The connection status is quiet until something is really wrong. Error and not-found pages match the rest of ChitChat. Phones with very large text lose nothing. It has **no database migrations**, no configuration changes and **no API changes**. Nobody is signed out. **One server behaviour changes for operators:** addresses that don't exist now return `404` instead of the chat page (see below).

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It contains maintainer-approved presentation work, tracked in [#173](https://github.com/Thiesi/ChitChat/issues/173) and [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Added

- **Leave a room from the web.** ([#299](https://github.com/Thiesi/ChitChat/issues/299), [#342](https://github.com/Thiesi/ChitChat/pull/342)) "Leave room…" sits at the foot of the Members panel, which is reachable at every width (a bottom sheet on phones). It asks first, and tells you that you'll need a new invitation to rejoin a private room. Then it opens your next room without a reload. A room's owner is told how to hand the room on first.
- **Error and not-found pages.** ([#344](https://github.com/Thiesi/ChitChat/pull/344), [#348](https://github.com/Thiesi/ChitChat/pull/348)) An address that doesn't exist shows "There's nothing here" with status `404`. A page that fails shows a plain error page with status `500` instead of a blank screen. That covers an uncaught error, running out of memory, and PHP's own time limit. A worker that PHP-FPM kills (`request_terminate_timeout`) still ends without a page. The pages show only the installation's name, are never cached, and aren't indexed. The full error goes to the PHP log as before. API responses, the command line and `APP_DEBUG` are unchanged.

## Changed

- **No more browser pop-ups.** ([#341](https://github.com/Thiesi/ChitChat/pull/341)) You edit a message in place, in its bubble: Enter saves, Shift+Enter adds a line, Esc cancels, and a failed save keeps your edit open. Deleting a message asks in a styled confirmation with Cancel selected first. Renaming a passkey uses a small form. A test now fails if a browser pop-up is added back.
- **A quieter connection status.** ([#309](https://github.com/Thiesi/ChitChat/issues/309), [#343](https://github.com/Thiesi/ChitChat/pull/343)) On Rooms and on Direct, which now has the same line, nothing shows while live. "Reconnecting…" appears only after three seconds without a connection. Without a network it says "Offline. You can't send until you're back.", and a send then says "You're offline. Your message wasn't sent." and keeps your draft. Screen readers hear "Still reconnecting…" once during a long outage and "Connected again." when it ends.
- **Empty screens suggest a next step.** ([#346](https://github.com/Thiesi/ChitChat/pull/346)) For example: "No messages yet. Say hello to start the conversation." or "Join the room to start the conversation." The search page's privacy notice is now one line, "Search covers only messages you can see.", with Learn more.
- **Phones.** ([#347](https://github.com/Thiesi/ChitChat/pull/347), [#349](https://github.com/Thiesi/ChitChat/pull/349), [#350](https://github.com/Thiesi/ChitChat/pull/350))
  - Below 768 px every dialog opens as a sheet from the bottom, with its actions always in view.
  - The layout holds down to 180 CSS px, which is a phone with very large text. The message box keeps its full width, the bottom navigation keeps all four destinations, the room name keeps priority in the header, and headings shrink instead of breaking mid-word.
  - On Direct, the privacy line reads "Not end-to-end encrypted" when space is short; screen readers still hear the full sentence.
- **Activity and search.** ([#350](https://github.com/Thiesi/ChitChat/pull/350)) Activity shows your notices first, with "Mark all as read" beside the heading and the explanation in a disclosure below the list. Notices you've read are no longer bold. Search results start sooner, and on narrow screens the scope choice becomes one control.

## Fixed

- Pressing Escape in a dialog opened from the phone Members panel no longer closes the panel too. ([#347](https://github.com/Thiesi/ChitChat/pull/347))

## Operator notes

- **Unknown addresses now return `404`.** Before, the web server's fallback (Apache `FallbackResource`, Nginx `try_files`) sent any unknown path, such as `/status` or `/.env`, to the chat page with status `200`. Now ChitChat answers those with its own 404 page. **If an uptime check or load balancer probes a made-up path, point it at `/health.php` or `/ready.php`.** `/`, `/index.php`, `/favicon.ico` and every real page and API endpoint are unchanged.
- **No web-server configuration change is needed.** Optionally, on Nginx, `error_page 404 /not-found.php;` in the PHP location shows ChitChat's page for a missing `*.php` address too; see [`docs/operations/nginx-php-fpm.md`](../operations/nginx-php-fpm.md). The Apache guide and example vhost describe the new behaviour.
- **Pools that pin `memory_limit` with `php_admin_value`** can't give the error page its extra 8 MiB after an out-of-memory failure, so that case may still end with a blank `500`.
- **No configuration changes** and no migrations. **Nobody is signed out.**
- Continue backing up PostgreSQL and attachment storage together.

## What to evaluate

Operators staging this release should check that:
- `/` opens the chat, and a made-up address such as `/nothing-here` shows "There's nothing here" with status `404`;
- your uptime checks still pass (they should use `/health.php` or `/ready.php`);
- a member can leave a room from the Members panel, and the owner is told to hand it on first;
- editing and deleting a message work without browser pop-ups;
- on a phone with large text, the message box, the bottom navigation and the room name stay usable.

## Upgrade from v3.12.0

1. Stop or drain application traffic (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
2. Deploy `v3.13.0` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` has nothing to apply.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.13.0`.

Upgrading from before `v3.10.0` also applies that release's migrations (`0059` and `0060`); read its release notes first.
