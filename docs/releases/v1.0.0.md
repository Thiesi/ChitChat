# ChitChat v1.0.0

`v1.0.0` is the first stable release of the clean ChitChat reconstruction. It promotes `v1.0.0-rc.1` after completing cross-browser, published-archive, recovery, upgrade, and real reverse-proxy validation.

There are no database-schema, API, or product-feature changes between the release candidate and this stable release.

## Supported deployment baseline

The supported initial deployment is one ChitChat application server with:

- PHP 8.2 or newer;
- PostgreSQL 15 or newer;
- Nginx and PHP-FPM or an equivalent correctly configured web stack;
- `public/` as the only web-exposed directory;
- attachment storage outside the web root;
- HTTPS and secure session cookies;
- an operator-scheduled maintenance command;
- PostgreSQL and attachment storage backed up together.

The Nginx/PHP-FPM reference configuration in `docs/operations/nginx-php-fpm.md` has been exercised in CI with an authenticated SSE connection and a concurrent room-message request.

## Validation completed for stable

The exact stable source passes:

- PHP lint and PHPStan level 8;
- JavaScript and stabilization-shell syntax checks;
- every migration and the complete PHPUnit suite against PostgreSQL 16;
- maintenance dry-run;
- the full two-session browser journey independently in Chromium and Firefox;
- installation from the published private `v1.0.0-rc.1` source archive with production Composer dependencies;
- database and attachment backup checksums and structural verification;
- restoration under new database and storage names;
- forward migration from the restored release candidate to stable source;
- verification of restored accounts, room history, direct messages, and exact attachment bytes;
- authenticated unbuffered SSE delivery through real Nginx and PHP-FPM.

## Fresh installation

Follow `INSTALL.md`. For a production installation:

```sh
composer install --no-dev --classmap-authoritative
composer migrate
composer maintenance:dry-run
```

Create attachment storage with restrictive permissions, make it writable by the PHP service account, and verify both `/health.php` and `/ready.php` before accepting traffic.

## Upgrade from v1.0.0-rc.1

1. Stop or drain application writes.
2. Back up PostgreSQL and attachment storage together.
3. Preserve `.env` and the existing attachment directory.
4. Deploy stable `v1.0.0` source.
5. Run:

   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   composer maintenance:dry-run
   ```

6. Verify `/health.php`, `/ready.php`, login, room history, SSE, an attachment download, and a direct message.

The automated rehearsal in `tests/stabilization/rehearse-release.sh` performs this path from the published RC archive through backup, restore, and stable-source migration.

## Privacy and retention defaults

- Direct messages are server-side PostgreSQL records and are **not end-to-end encrypted**.
- Administrative DM inspection is enabled for Super-Administrators by default, requires a reason, and audits every returned page.
- Room messages, direct messages, and audit entries are retained permanently by default.
- Nonzero retention policies take effect only when maintenance runs.
- Attachment downloads always re-evaluate current room and minimum-age authorization.

Operators must review and communicate these defaults before onboarding users.

## Known limitations

- single application-server target;
- PostgreSQL only;
- no horizontal scaling or Redis-backed event delivery;
- direct messages are text-only and have no attachments or user blocking;
- no message editing or user-side deletion;
- room moderation deletion is a soft delete;
- WebKit is not part of the automated browser matrix;
- maintenance scheduling and monitoring remain operator responsibilities;
- no supported upgrade path exists from the incomplete legacy `v0.10.25` snapshot.

Detailed changes are listed in `CHANGELOG.md`.
