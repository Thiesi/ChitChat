# ChitChat v3.15.1

`v3.15.1` is a bug-fix update on top of `v3.15.0`. The room's lantern in the conversation header no longer has its presence halo cut off square. The operations guides now recommend a web-server header that stops browsers from reusing old stylesheets and scripts after an upgrade. It has **no database migrations, no configuration changes and no API changes**, and nobody is signed out.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). ChitChat remains feature-complete. See [`docs/roadmap.md`](../roadmap.md).

## Fixed

- **The room lantern's halo is no longer cut square.** ([#414](https://github.com/Thiesi/ChitChat/pull/414)) On the narrow conversation header, the glow around the room's lantern, which lights up while people are in the room, was cut off in a hard-edged square. The room's name is clamped to two lines there, and the lantern sat inside that clip. Now only the name is clamped, and the lantern's halo is soft all round. With a large default text size, desktop windows get the narrow header too, which is why the cut also showed there.

## Operator notes

- **Recommended web-server change: `Cache-Control: no-cache` for `/assets/css/` and `/assets/js/`.** ([#411](https://github.com/Thiesi/ChitChat/issues/411), [#413](https://github.com/Thiesi/ChitChat/pull/413)) ChitChat's stylesheets and scripts are served without a `Cache-Control` header. Browsers then guess how long a file stays fresh, so after an upgrade they can run old CSS or JavaScript against the new pages for hours. With `no-cache`, browsers keep the files but check them before each use. An unchanged file costs only a `304`, and a changed one is fetched at once. Add it when you deploy this release:
  - Nginx: [`docs/operations/nginx-php-fpm.md`](../operations/nginx-php-fpm.md#nginx-server) (a `location` with `add_header`, placed after the dotfile deny);
  - Apache: [`docs/operations/netbsd-apache.md`](../operations/netbsd-apache.md#apache) and [`deploy/netbsd/apache-vhost.conf.example`](../../deploy/netbsd/apache-vhost.conf.example) (`Header set` in a `<LocationMatch>`, with `mod_headers`).

  The project's own deployment already sends it.
- **No migrations**, **no configuration changes**, and **nobody is signed out**.

## For app developers

No API or contract changes.

## What to evaluate

Operators staging this release should check that:
- in a room where someone is present, the lantern in the conversation header glows softly all round on a phone, and in a desktop window narrow enough to get the phone header;
- after adding the header, `curl -I https://chat.example.org/assets/css/app.css` shows `Cache-Control: no-cache`.

## Database changes

None.

## Upgrade from v3.15.0

1. Stop or drain application traffic (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
2. Deploy `v3.15.1` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` has nothing to apply.
4. Add the recommended `Cache-Control` header for `/assets/css/` and `/assets/js/` (see Operator notes), and reload the web server.
5. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
6. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.15.1`.

Upgrading from before `v3.14.0` also applies that release's migration (`0061`); back up first and read its release notes.

## Fresh installation

Follow `INSTALL.md`, or `docs/operations/netbsd-apache.md` on NetBSD with Apache. The Nginx and Apache guides include the recommended header.

## Known limitations

- **A message's "More" by tap on a real phone is unverified** ([#394](https://github.com/Thiesi/ChitChat/issues/394)). Browser emulation can't settle whether the actions on a message's name line open by tap. On touch screens, a tap on the bubble opens a sheet with the same actions.
- Otherwise unchanged from `v3.15.0`. The [accessibility statement](../accessibility.md) lists what is and isn't tested.
