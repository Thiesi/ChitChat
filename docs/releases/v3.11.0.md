# ChitChat v3.11.0

`v3.11.0` is a small privacy release. ChitChat no longer reveals whether a private room, or a message or file in one, exists to someone who can't see it. The web client says plainly when a room, message or file is no longer available. Guests whose visit was ended are told so correctly. It has **no database migrations** and no configuration changes. Nobody is signed out. **For app developers, some error codes change** for one group of callers (see below).

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It contains maintainer-approved privacy and presentation fixes, tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Security and privacy

- **Private rooms can't be detected from outside.** ([#326](https://github.com/Thiesi/ChitChat/issues/326), [#327](https://github.com/Thiesi/ChitChat/pull/327)) Before, most room routes answered a private room you can't see differently from a room that doesn't exist (403 instead of 404). So anyone signed in could find out that a private room, or a message or file in it, existed. Now every such request gets exactly the answer for something missing. Members, invitees, global moderators, and public and unlisted rooms are unchanged.

## Changed

- **"No longer available" says so plainly.** ([#331](https://github.com/Thiesi/ChitChat/pull/331)) Sending, joining, reacting, uploading, editing, deleting or reporting in a room or on a message that is gone, or that you can't see, now says "This room isn't available any more." or "That message isn't available any more." A link to a message or ping in a room you can't see, or that's gone, says "This room isn't available any more." after a short wait, and a link to a message that's no longer in the room's history says "That message isn't available any more." A plain room link (without a message) still opens without a notice, and opening a file that's gone from its link still shows the server's plain error answer, with its preview not loading.

## Fixed

- **Guests whose visit a moderator ended** are told "Your guest visit has ended.", not "signed out from another device". Other sign-out reasons, such as maintenance, are kept. ([#328](https://github.com/Thiesi/ChitChat/issues/328), [#330](https://github.com/Thiesi/ChitChat/pull/330))

## For app developers: changed error codes

Most changes apply **only** to a signed-in caller who isn't a member of, isn't invited to and can't moderate a **private** room; for every other caller, and for every public or unlisted room, these stay as they were:
- `403 room_forbidden` becomes `404 room_not_found` (details, pings, history, mutation metadata, attachment metadata, member search).
- `403 membership_required` becomes `404 room_not_found` (send, ping, upload).
- `403 invitation_required` becomes `404 room_not_found` (join).
- `409 not_a_member` becomes `404 room_not_found` (leave).
- `403 presence_membership_required` becomes `404 room_not_found` (presence).
- `403 forbidden` becomes `404 room_not_found` (manage, broadcast, room mute).
- Message-ID routes: `403 room_forbidden`, `membership_required` or `forbidden` become `404 message_not_found`.
- Attachment download: `403 room_forbidden` and `410 attachment_deleted` become `404 attachment_not_found`.

Also:
- Restoring a deleted room (`rooms/restore.php`), for anyone who can't manage it, answers like a missing deleted room: `404 room_not_found`, also for a deleted public room, where it used to be `403 forbidden`.
- Lifting a mute in a room you can't see answers `404 mute_not_found` (`403 forbidden` before).
- For **every** caller, a message-ID route (react, unreact, edit, delete, delete own, report) on a message in a deleted room (or, for a guest, in a room closed to guests) now answers `404 message_not_found` instead of `404 room_not_found`, and lifting a mute in a deleted room answers `404 mute_not_found` instead of `404 room_not_found`. The status stays 404.

People removed from a private room, or who left it, count as non-members, so they get these answers too. A client that treats 404 as "not available" needs nothing. See [Room visibility in errors](../api/rooms.md#room-visibility-in-errors-326).

## What to evaluate

Operators staging this release should check that:
- a member can still read and post in their private rooms, and an invitee can still join;
- an account outside a private room gets "This room isn't available any more." for a link to a message in it (for example `/?room_id=N&message_id=M`), the same as for a room that doesn't exist;
- a guest whose visit is ended sees "Your guest visit has ended.".

## Database changes

None.

## Operator notes

- **No configuration changes**, and no migrations.
- **Nobody is signed out** by this upgrade.
- Continue backing up PostgreSQL and attachment storage together.

## Upgrade from v3.10.0

1. Stop or drain application traffic (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
2. Deploy `v3.11.0` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` has nothing to apply.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.11.0`.

Upgrading from before `v3.10.0` also applies that release's migrations (`0059` and `0060`); read its release notes first.

## Fresh installation

Follow `INSTALL.md`, or `docs/operations/netbsd-apache.md` on NetBSD with Apache.
