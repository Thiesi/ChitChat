# ChitChat v3.12.0

`v3.12.0` is a small web-client release. System status now shows phone alerts and backups. Operational settings gets a Health checks card for the backup and maintenance maximum ages. Search can be limited to the room you're in. The navigation rail's name reads as a heading, and failed sends and uploads say the draft wasn't sent. It has **no database migrations**, no configuration changes and **no API changes**. Nobody is signed out.

## Project status: feature-complete

This release does not change [project status](../README.md#project-status-feature-complete). It contains maintainer-approved presentation and operability additions, tracked in [#163](https://github.com/Thiesi/ChitChat/issues/163). See [`docs/roadmap.md`](../roadmap.md).

## Added

- **Phone alerts and backups on System status.** ([#310](https://github.com/Thiesi/ChitChat/issues/310), [#336](https://github.com/Thiesi/ChitChat/pull/336)) Two new cards show what the `v3.10.0` API already reported. **Phone alerts** shows the Web Push queue (waiting, due now, failed, last sent) and says **Overdue** when a due alert has waited more than five minutes, which means the alert sender isn't running. A server without push says **Not set up**, which is fine if you don't use it. **Backups** shows the latest run, the latest success and the maximum age, and says **Current**, **Overdue**, **Failed**, **Unknown** (no recorded run yet, which also counts as overdue) or **Not tracked** (the check is off).
- **Health checks in Operational settings.** ([#310](https://github.com/Thiesi/ChitChat/issues/310), [#312](https://github.com/Thiesi/ChitChat/issues/312), [#336](https://github.com/Thiesi/ChitChat/pull/336)) A Super-Administrator can set **Backup maximum age, in hours** (0–720, default 26; 0 turns the check off) and **Maintenance maximum age, in hours** (1–720). The maintenance age is only saved when you change it, and **Use the server default** returns to `MAINTENANCE_MAX_AGE_HOURS`.
- **Search one room.** ([#318](https://github.com/Thiesi/ChitChat/issues/318), [#339](https://github.com/Thiesi/ChitChat/pull/339)) The search button in a room's header opens search limited to that room, shown as an "In # Room" chip; its ✕ searches everywhere instead. The list pane's search button stays global. If the room is gone or you can no longer see it, the chip is dropped and the page says "This room isn't available any more." Matches are now highlighted where the server found them.

## Changed

- **The rail's name reads as a heading.** ([#338](https://github.com/Thiesi/ChitChat/pull/338)) A thin line now separates the icon and name at the top of the navigation rail from the buttons below, and the pointer no longer suggests it can be clicked. The phone layout is unchanged.
- **Failed sends and uploads say so.** ([#338](https://github.com/Thiesi/ChitChat/pull/338)) When a message or file can't be sent, the notice now says "Your message wasn't sent." or "Your file wasn't sent.", matching ChitChat Mobile. The unsent text or file stays where it was.
- **Operator documentation** ([#337](https://github.com/Thiesi/ChitChat/pull/337)) describes the new Health checks fields and links the settled-resume client contract from the installation guide.

## Internal

- Passwords are hashed in one place ([#335](https://github.com/Thiesi/ChitChat/pull/335)). In production this is exactly `password_hash` with `PASSWORD_DEFAULT` and PHP's default options, as before; nothing can configure it. Only the test suite lowers the cost, in its own process.
- The local test suite runs faster ([#332](https://github.com/Thiesi/ChitChat/pull/332)): parallel PHP lint (`composer lint` now runs `bin/lint`) and lighter database cleanup between tests.

## What to evaluate

Operators staging this release should check that:
- System status shows the Phone alerts and Backups cards, and that Backups is **Current** after `bin/chitchat-backup` has run;
- on an instance **without scheduled `chitchat-backup` runs** (for example a test instance), setting **Backup maximum age** to `0` turns the card to **Not tracked**;
- the search button in a room's header searches only that room, and ✕ searches everywhere.

## Operator notes

- **No configuration changes**, and no migrations.
- **Nobody is signed out** by this upgrade.
- **Instances without scheduled backups through `bin/chitchat-backup`** report backups as overdue since `v3.10.0`. Set Operational settings › Health checks › Backup maximum age to `0` on them.
- Continue backing up PostgreSQL and attachment storage together.

## Upgrade from v3.11.0

1. Stop or drain application traffic (see `INSTALL.md`, Upgrading), and back up PostgreSQL and attachment storage together.
2. Deploy `v3.12.0` source.
3. Run:
   ```sh
   composer install --no-dev --classmap-authoritative
   composer migrate
   ```
   `composer migrate` has nothing to apply.
4. Reload PHP-FPM, and restart the push dispatcher listener if you run one.
5. Verify `/health.php`, `/ready.php`, and that `GET /api/v1/session.php` reports `application.version` `3.12.0`.

Upgrading from before `v3.10.0` also applies that release's migrations (`0059` and `0060`); read its release notes first.
